# 디자인 리뷰 브리프 — bedrock-compare.awskr.net

목표: 라이브 사이트의 **시각 디자인**을 사용자(froguin)의 기존 awskr.net 사이트들과
같은 완성도로 끌어올린다. 정보 구조·데이터 정합성은 이미 별도 작업으로 해결됐고,
이번 리뷰 범위는 **외관·브랜딩·컴포넌트 품질**이다.

## 대상

- 라이브: https://bedrock-compare.awskr.net
- 소스: `web/index.html` (바닐라 HTML/CSS/JS 단일 파일, 빌드 산출물 `dist/bedrock-pricing.html`)
- 제약: **바닐라만** — 프레임워크·빌드 체인·외부 CSS/폰트 CDN 도입 금지.
  단일 파일로 `file://`에서도 열려야 하므로 런타임 네트워크 의존 추가 금지.

## 벤치마크: froguin의 기존 사이트 (실제 렌더 관찰)

스크린샷(이 호스트에서 읽을 수 있음):
- `$KIROCREW_SCRATCH/site-quick.png` — https://quick.awskr.net
- `$KIROCREW_SCRATCH/site-kiro.png` — https://kiro.awskr.net
- `$KIROCREW_SCRATCH/site-release.png` — https://release.awskr.net
- `$KIROCREW_SCRATCH/bedrock-live.png` — 우리 현재 화면

### 하우스 스타일 A — "핸드북" (quick, kiro)
두 사이트가 같은 디자인 시스템을 공유한다.

- 상단 고정 내비: 좌측 **브랜드 마크(로고 + 이름)**, 그 옆 **`Search ⌘K` 칩**,
  우측 섹션 링크들 + **다크/라이트 토글**
- 히어로: 라디얼 그라디언트 배경 글로우, **그라디언트 대형 헤드라인**
  (quick=마젠타→퍼플, kiro=퍼플), 3단 타이포 위계(제목 / 굵은 부제 / 설명문)
- 히어로 우측에 **큰 브랜드 아트워크**(발광 처리된 로고)
- CTA: **알약형 버튼** 3개 — 채운 primary 1개 + 고스트 2개
- 카드 그리드: 라운드 코너, 미묘한 보더, 이모지/아이콘 + 제목 + 2줄 설명, 넉넉한 여백
- 섹션 제목으로 리듬 부여 ("어디서부터 시작할까요?")
- 푸터: 저작권 + **비공식 디스클레이머**

### 하우스 스타일 B — "데이터" (release, Cloudscape 계열)
밀집 데이터 화면의 기준점.

- 상단 바: 브랜드명 + 다크 토글 + **GitHub 링크**
- 성공 플래시 배너(초록, 닫기 버튼)
- 섹션 헤더: 제목 + **괄호 카운트 `(239)`** + 우측 **새로고침 버튼**
- 전폭 검색 입력 + **숫자 페이지네이션(1..24)** + 설정 기어
- **정렬 가능한 컬럼 헤더**(정렬 방향 인디케이터)
- **아이콘+색 배지**로 상태 표현 (`✓ 정식 출시`, `ⓘ 미리보기`)
- 2줄 셀: 한국어 제목 + 원문 영어 보조행
- **오버플로 알약** 패턴 — `미국 동부(버지니아 북부) +16`
- 하단 접히는 **상세 정보 패널**

## 우리 현재 화면의 관찰된 문제

1. 브랜드 마크·상단 내비·다크 토글이 **전부 없음** (세 사이트 모두 있음)
2. 폼 컨트롤이 **OS 기본 위젯 그대로** — `<select>`, number input, text input.
   "기술적 느낌"의 가장 큰 원인. 기존 사이트들은 알약/세그먼트로 스타일링됨
3. 히어로가 없음 — 시각적 앵커 없이 바로 컨트롤부터 시작
4. 액센트 컬러가 하우스 팔레트(마젠타/퍼플 계열)와 **불일치** (현재 파란색 계열)
5. 타이포 위계 약함 — 그라디언트 헤드라인 없음
6. 상태 표현이 **색 있는 평문**, 배지 아님 (release는 아이콘+색 배지)
7. 오버플로 알약 패턴 미사용 — 리전/모델 카운트에 바로 적용 가능
8. 푸터 없음 — 디스클레이머가 헤더 본문에 섞여 있음
9. GitHub 링크·갱신시각 affordance 없음

## 산출물 요구

추상적 조언 금지. 이 파일에 바로 적용 가능한 **구체적 결정**을 낼 것:

- CSS 커스텀 프로퍼티로 표현한 **팔레트**(다크/라이트 양쪽), 액센트 선택 근거
- **타이포 스케일**(px/rem 실수치), 한글 가독성 고려
- **컴포넌트별 교체안** — 특히 native `<select>`/number input을 바닐라로
  어떻게 대체할지(마크업+CSS 수준에서)
- 하우스 스타일 A와 B 중 **어느 쪽을 기준으로 삼을지**, 또는 어떻게 섞을지.
  우리는 밀집 데이터(135모델x36리전) + 질문형 입력이 섞인 화면이다
- **삭제/강등 목록**
- 우선순위: 체감 변화가 큰 순서로 단계 나누기
